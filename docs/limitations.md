# 已知限制与威胁边界

本文档坦诚记录 PasswordNotebook 目前的技术边界、已知限制以及客观存在的安全对抗边界，便于使用者建立清晰的威胁模型预期。

---

## 1. 内存残留与取证边界

在现代操作系统和高级语言运行环境下，敏感数据在内存中的绝对「零残留」是不可能完全保证的。PasswordNotebook 通过 Rust 的 `zeroize::Zeroizing` 对核心敏感数据（DEK、派生密钥、整库 JSON 明文、条目密码、剪贴板缓冲）进行了离开作用域主动覆写清零，但依然存在以下**不可逾越的客观边界**：

1. **Win32 原生输入控件缓冲**：
   - 界面上的密码输入框（Win32 `EDIT` 控件）由 Windows 系统模块（`user32.dll`）内部管理其文本内存。
   - 虽然程序读取输入时使用了安全宽字符容器，但 Windows 控件内部私有堆内存的生存周期不受应用程序直接掌控，在窗口或控件被彻底销毁前，该控件内存无法被本进程主动擦除。
2. **JSON 序列化与反序列化瞬态副本**：
   - 保险库采用 `serde_json` 组织结构化明文数据。在解析 JSON 字符串为内存结构体、或将结构体序列化为密文载荷的过程中，底层分配器会产生瞬态的堆内存字符串与碎片副本。这些短命副本在被操作系统重新分配或覆写前，可能在堆空闲列表中短暂停留。
3. **威胁评估结论**：
   - **内存清零的核心价值是抬高取证门槛、大幅缩短敏感数据的暴露时间窗口，而不是彻底免疫物理取证**。
   - 拥有本地 Administrator/SYSTEM 权限、能够实施内核级内存倾倒（Crash Dump / Memory Forensics）、或能够直接读取磁盘休眠文件（`hiberfil.sys`）的攻击者，在理论上仍可能在特定时间窗口内恢复出部分明文片段。若运行环境本身已被完全攻陷，任何用户态密码管理器均无法独善其身。

## 2. 本机免密缓存（Quick Unlock）的信任边界

本机免密解锁利用了 Windows 提供的 DPAPI 数据保护接口，其安全边界取决于本机 Windows 账户：

1. **绑定主体为 Windows 账户而非开机密码**：
   - DPAPI 凭据绑定的是当前已登录的 **Windows 账户上下文**。
   - **修改 Windows 账户的登录密码并不会让 DPAPI 缓存失效**（Windows 内部主密钥会自动平滑迁移）。
   - 若要作废免密缓存，请在主界面点击「锁定」按钮，或在设置界面中关闭「本机免密解锁」。
2. **同会话进程边界**：
   - 在同一个已登录的 Windows 用户桌面会话中，以相同用户权限运行的恶意软件理论上同样具备调用 `CryptUnprotectData` 的系统权限。
   - **防御建议**：在公共电脑或多用户共享电脑上，建议在设置中勾选**「免密解锁时要求 Windows Hello 验证」**（强制要求指纹/面容/PIN 物理在场授权），或者直接**关闭免密解锁**。
3. **离线/未运行期间的锁屏感知**：
   - 锁屏即时清除机制依赖程序后台消息循环捕获会话变更通知。若在**程序未处于运行状态**时计算机发生了锁屏或切换用户，程序在下次冷启动时无法追溯此前的锁屏事件。

## 3. 搜索能力说明

- **子串包含匹配**：
  - 主界面的搜索框采用**多字段大小写不敏感子串匹配**（检查输入文本是否为标题、用户名、网址、分类、标签或备注的子串）。
  - **不是**拼音搜索，**不是**编辑距离模糊纠错（Fuzzy / Levenshtein），亦不包含全文分词倒排索引。输入关键词时需确保包含连续的目标字符片段。

---

## 4. 架构与功能限制

- **自创文件格式与生态隔离**：
  - 保险库格式 `.pkk` 为自研单文件加密格式（详见 [docs/security.md](security.md)）。
  - 目前暂无第三方工具支持直接解析，亦暂未内置 CSV 或 JSON 的明文导入与导出向导（若需迁移数据，需通过 API 或脚本工具读写）。
- **KDF 参数初始化固化**：
  - Argon2id 的计算参数（64 MiB 内存、3 次迭代、4 路并行）在创建保险库时固化写入文件头明文区，当前版本未在设置界面中提供动态调参功能。
- **单数据库绑定**：
  - 程序定位为轻量便携工具，默认单一绑定 exe 所在目录的 `data.pkk`（若目录不可写则自动回退至用户「文档」目录），不提供多库切换、多账本并行管理。
- **单语言界面**：
  - 目前界面文字全部为简体中文，尚未抽取资源字典进行多语言国际化（i18n）。
