# 安全设计与加密架构

本文档详细说明 PasswordNotebook 的密码学方案、保险库文件格式、密钥派生与包裹机制、本机免密解锁流程以及内存安全边界。

---

## 1. 核心密码学标准

PasswordNotebook 坚持采用公认、开放且经过实战检验的标准现代密码学算法，杜绝私有或未经广泛审查的密码学实现：

- **对称加密与认证**：**AES-256-GCM**（遵循 NIST SP 800-38D）。采用 256 位密钥强度，提供具备完整性校验与防篡改特性的认证加密（AEAD）。每次加密保存均采用 CSPRNG 生成全新的 12 字节随机数（Nonce）。
- **密码哈希与密钥派生**：**Argon2id**（遵循 RFC 9106）。兼具抗侧信道攻击（Argon2i）与抗 GPU/ASIC 硬件暴力破解（Argon2d）特性。
  - 默认参数配置：内存硬度 `m = 65,536 KiB`（64 MiB），时间迭代 `t = 3`，并行通道 `p = 4`，派生输出长度 32 字节。
- **随机数源**：通过系统提供的密码学安全随机数生成器（Linux 下为 `getrandom`，Windows 下由操作系统提供的高熵熵池），确保密钥、盐值与随机数的不可预测性。

## 2. 保险库文件格式与布局（`.pkk`）

保险库保存为单个独立自包含的可移植文件（固定命名为 `data.pkk`）。

### 2.1 整体存储布局

```text
+---------------------+-------------------+-------------------+-----------------+---------------------+
|  文件头 (Header)    | 主密码槽 (Slot 1) | 恢复码槽 (Slot 2) | 载荷长度 (4B)   | AES-256-GCM 密文载荷 |
|      105 字节       |      48 字节      |      48 字节      | 32-bit LE int   |     变长字节流      |
+---------------------+-------------------+-------------------+-----------------+---------------------+
```

- **数据密钥（DEK, Data Encryption Key）**：随机生成的 32 字节高熵对称密钥，用于加密整份数据库载荷（明文为包含条目、分类、标签与设置的 JSON 结构）。
- **密钥槽（Key Slots）**：DEK 本身不以明文存放在磁盘上，而是分别被「主密码」和「恢复码」包裹后存放在独立的槽位中。每个槽位长度为 48 字节（32 字节密文 + 16 字节 GCM 认证标签）。

### 2.2 文件头结构（105 字节明文前缀）

文件头为公开明文信息（不包含任何秘密密钥），但**作为 AAD 深度参与后续认证**：

| 偏移 | 长度 | 字段名称 | 说明 |
| :--- | :--- | :--- | :--- |
| `0x00` | 4B | 魔数（Magic） | 固定 ASCII 字节 `PNBK` |
| `0x04` | 1B | 格式版本（Format Version） | 当前为 `1` |
| `0x05` | 4B | `m_cost_kib` | Argon2id 内存参数（默认 65536 KiB） |
| `0x09` | 4B | `t_cost` | Argon2id 迭代轮数（默认 3） |
| `0x0D` | 4B | `p_cost` | Argon2id 并行通道数（默认 4） |
| `0x11` | 16B | `vault_id` | 保险库全局唯一随机 UUID，用于实例与缓存校验 |
| `0x21` | 4B | `key_generation` | 密钥版本代数（初始为 1，每次修改主密码递增） |
| `0x25` | 16B | `password_salt` | 主密码 Argon2id 专用盐值 |
| `0x35` | 12B | `password_nonce` | 主密码槽 AES-GCM 随机数 |
| `0x41` | 16B | `recovery_salt` | 恢复码 Argon2id 专用盐值 |
| `0x51` | 12B | `recovery_nonce` | 恢复码槽 AES-GCM 随机数 |
| `0x5D` | 12B | `payload_nonce` | 主载荷 AES-GCM 随机数（每次保存换新） |

## 3. 三套独立 AAD 认证机制

为了实现高度的模块解耦与防篡改，系统将文件头中的元数据作为附加认证数据（AAD），分别构造了三套完全独立的 AAD：

1. **主密码槽 AAD**：
   `magic + version + kdf_params + vault_id + password_salt + password_nonce`
2. **恢复码槽 AAD**：
   `magic + version + kdf_params + vault_id + recovery_salt + recovery_nonce`
3. **载荷 AAD**：
   `magic + version + kdf_params + vault_id + payload_nonce`

### 架构优势

- **防御元数据篡改与降级攻击**：文件头虽然公开可读，但因为被捆绑进了各个密文块的 AEAD 认证中，攻击者若试图修改 KDF 参数降低破译难度、伪造 `vault_id` 或调换盐值，解密时 GCM 标签校验必定失败。
- **解耦操作，安全高效**：
  - **修改主密码**：只需重新派生 KEK 并覆写主密码槽（递增 `key_generation` 并重置盐和随机数），恢复码槽与载荷密文**原封不动**，无需重写大量数据。
  - **重置恢复码**：仅需生成新码并覆写恢复码槽，主密码槽与载荷密文无需重加密。
  - **更新条目数据**：只需使用当前 DEK 重新加密载荷并更换 `payload_nonce`，无需重新运行高耗时的 Argon2 计算。

## 4. 本机免密解锁机制（Quick Unlock）

为了在日常高频使用中兼顾安全与便利，系统提供了基于 Windows 原生安全体系的本机免密解锁方案：

1. **凭据保护**：解锁成功后，32 字节 DEK 使用 Windows **DPAPI**（`CryptProtectData`，作用域限于当前 Windows 用户 `CurrentUser`）进行加密，保存在 `%LOCALAPPDATA%\PasswordNotebook\quickunlock.dat` 中。
2. **代数绑定（Key Generation）**：缓存文件内捆绑了 `vault_id` 与当前的 `key_generation`。只要用户在程序内修改了主密码，`key_generation` 发生变化，旧缓存自动作废，无法再用于解密。
3. **系统事件联动与主动销毁**：程序注册了 Windows 终端服务会话通知（`WTSRegisterSessionNotification`）并监听系统屏保。一旦捕获到**锁屏（Win + L）**或**屏保启动**，程序会立刻从内存中擦除解密状态，并物理删除本地的 DPAPI 缓存文件。
4. **可选 Windows Hello 二次验证**：支持启用 Windows 原生生物识别（人脸/指纹）或 PIN 验证（通过带主窗口句柄的 `UserConsentVerifier` WinRT 接口），在读取 DPAPI 凭据前强制要求物理在场证明。

## 5. 内存安全设计与敏感数据生命周期

针对内存驻留与取证对抗，程序采取了防御纵深策略：

- **RAII 主动覆写清零（Zeroizing）**：
  - 核心敏感结构（数据密钥 DEK、Argon2 派生密钥 KEK、解密后的库明文序列化缓冲、条目中的密码字段 `entry.password`、剪贴板中转缓冲）均使用 `zeroize::Zeroizing` 进行封装。
  - 在变量超出作用域被 Drop 时，底层触发编译器不会优化的 `volatile` 写入，立刻将对应内存物理覆写为零。
- **剪贴板定时熔断**：复制密码后，程序启动毫秒级倒计时定时器；超时后自动比对剪贴板当前内容并彻底清空，防止被其他后台软件恶意监听或历史记录软件抓取。
- **导出缓冲同样清零**：CSV / JSON 的导出文本、以及导入时读取的原始文件字节与解码文本，都以 `Zeroizing` 承载并在离开作用域时覆写。
- **内存驻留客观边界**：关于操作系统的内存边界（如原生控件缓冲区与序列化中间副本），请参阅 [docs/limitations.md](limitations.md)。

## 6. 明文导入 / 导出的安全约束

导入导出是保险库唯一的「明文出口」与「外部数据入口」，因此界面与核心层都按最坏情况设防：

1. **密码需二次确认才写出**：导出默认包含明文密码，但必须额外勾选「我明白导出文件是明文，会妥善保管」才会执行；取消勾选「包含明文密码」后，密码列/字段会被**整体省略**（而不是留空），此时导出文件只有账号信息。
2. **省略而非留空**：留空会在「覆盖导入」时被误读为「把密码清空」。字段缺失在语义上等价于「本次不涉及密码」，配合第 4 条形成完整的防误删链条。
3. **CSV 公式注入防护**：以 `=` `+` `-` `@` 或单引号开头的单元格会加上前导单引号（OWASP 建议），避免用户在 Excel 中打开导出文件时触发 `=cmd|...` 之类的公式执行；导入时该前缀会被精确还原。
4. **覆盖不清空密码**：采用覆盖策略导入时，若文件中该条目的密码为空，则**保留库内原密码**。
5. **导入前自动备份**：写库之前先把现有 `.pkk` 原样复制为 `data.pkk.bak`（仍是加密文件，不额外泄露信息）。备份失败则中止导入，绝不出现「改了但退不回去」的状态。
6. **单次原子落盘**：整批导入只在结束时调用一次 `save()`（内部走「临时文件 → fsync → 改名」的原子写），不存在导入到一半的中间状态。
7. **导入一律分配新 id**：忽略文件中携带的 id，避免与库内条目撞 id —— 否则后续编辑与「彻底删除」会作用到错误的对象上。
8. **编码白名单**：只接受 UTF-8（可带 BOM）。中文 Windows 上 Excel 默认导出的 GBK/ANSI 文件会被明确拒绝，而不是按 UTF-8 强行解码成乱码条目。
